# AttoLabs — техническое задание на редизайн сайта

Промпт/бриф для разработки нового сайта AttoLabs с нуля: современный стек, сохранённая реальная фирменная айдентика, исправленные проблемы находимости информации.

---

## 1. Задача проекта

Пересобрать сайт attolabs.eu (инженерная/AI-компания, услуги: cloud, custom software, digital transformation, mobile, MVP, web) с нуля на современном стеке (Next.js + GSAP + Framer Motion), сохранив реальную фирменную айдентику компании, но устранив системные проблемы находимости информации и технические огрехи текущей версии.

Ключевая цель: потенциальный клиент должен за один клик понять, работает ли AttoLabs с его отраслью и решает ли нужную задачу — через интерактивную фильтрацию услуг/индустрий/кейсов, а не через статичные списки.

---

## 2. Фирменная айдентика (сохранить как есть)

**Цвета:**
- Фон (основной, кремовый): `#F4ECE7`
- Акцент (коралловый — CTA, полноэкранные смысловые паузы, хайлайты): `#F0543D`
- Текст/навигация (тёмный): `#1A1A1A`
- Белый (текст на коралловом фоне, логотип на тёмном/цветном фоне): `#FFFFFF`

*(значения приблизительные по скриншотам — снять точные HEX пипеткой с реального сайта перед вёрсткой)*

**Типографика (система, не менять логику):**
- Моноширинный технический шрифт (тип Space Mono / IBM Plex Mono) — для: навигации, эйбраунов над секциями, лейблов кейсов ("01 БАНКИНГ"), футер-ссылок, кнопок. Капс здесь оправдан и должен быть последовательным.
- Гротеск с плотным трекингом — для крупных заголовков (H1, слоган в контактном блоке).
- Основной текст описаний — обычным регистром, без капса. Капс не используется для тела текста — только для лейблов/заголовков/кнопок.

**Логотип:** знак (стилизованный цветок/вертушка) + вордмарк "AttoLabs" обычным регистром, не моно. Белый вариант — для тёмных/цветных фонов.

**Компоненты:** прямые углы (без border-radius), тонкая обводка у кнопок, нумерация 01/02/03 только там, где реально есть последовательность (кейсы, шаги процесса), полноэкранные цветные (коралловые) блоки как визуальные паузы между секциями.

## 3. Известные проблемы текущего сайта — не повторять

1. Несовпадение фото и контента кейса (например, кейс про уличное освещение иллюстрирован фото ветряных турбин).
2. Задублированные модальные формы CTA (три идентичных копии одного попапа в разметке).
3. Title и meta-теги остаются на английском на локализованных (RU/DE) версиях — нужна полная локализация meta на всех языках.
4. В исходном коде — блок нечитаемого текста-мусора, оставшийся, судя по всему, от вёрстки/плагина — убрать полностью.
5. Услуги и индустрии на главной — статичные списки с цифрами без ссылки на кейсы: клиент не может понять, какие именно кейсы стоят за "Индустрии: 2".
6. Нет раздела о процессе работы и команде — сайт продаёт "что", но не "как" и не "с кем".

## 4. Структура сайта

**Главная:**
- Hero: видео-фон (как сейчас), H1 "ENGINEERS FOR AI ERA", подзаголовок капсом, две кнопки (начать проект / смотреть кейсы)
- Блок статистики: 4 страны · 7 индустрий · 6 услуг
- Интерактивная матрица "Услуги × Индустрии" с чипами-фильтрами → фильтрует сетку кейсов внизу, с текстовым статусом ("Показано: N кейсов, БАНКИНГ + WEB-РАЗРАБОТКА")
- Блок "Как проходит проект" — 4 шага, вертикальный трек с прогресс-линией по скроллу
- Карусель логотипов клиентов
- Контактная форма с фирменным слоганом "РАСШИРЯЙТЕ ВОЗМОЖНОСТИ БУДУЩЕГО С НАМИ"

**Кейсы (расширенная версия):** те же фильтры + полные карточки (фото, теги, стек технологий, длительность проекта, роль AttoLabs)

**О нас (новый раздел):** кто мы, команда/экспертиза по ролям, офисы (4 страны), принципы работы

**Сотрудничество:** что происходит после заявки (шаги), форматы работы (fixed price / time&material / выделенная команда), форма

**Карьера:** без изменений в структуре

## 6. Анимация и интерактивность

- **GSAP + ScrollTrigger** — сценарии, завязанные на скролл: раскрытие hero при загрузке (один оркестрованный момент, не разрозненные fade-in), счётчик статистики при появлении в зоне видимости, прогресс-линия по шагам процесса (scrub).
- **Framer Motion** — состояния компонентов: переключение чипов-фильтров, hover/tap на карточках кейсов, переходы между страницами, мобильное меню.
- Правило: один акцентный анимационный момент на загрузке страницы, everywhere else — анимация только в ответ на действие пользователя (клик, фильтр), не декоративный fade-up на каждой секции при скролле.
- Обязательно уважать `prefers-reduced-motion`.

---

## 7. Технический стек

- Next.js (App Router) + Tailwind, настроенный под токены из раздела 2
- Framer Motion — интерактивные состояния
- GSAP + ScrollTrigger — скролл-сценарии
- Структурированные данные для услуг/индустрий/кейсов (JSON или headless CMS) — чтобы фильтрация была основана на реальных связях, а не хардкоде
- Полная локализация meta-тегов (title, og:title, description) на EN/DE/RU
- Доступность: видимый фокус на клавиатуре, семантические заголовки, alt-тексты, поддержка reduced-motion

---

## 8. Критерии готовности

- [ ] С главной страницы клиент может за 1 клик увидеть кейсы, соответствующие его отрасли и нужной услуге
- [ ] Ни один CTA не дублируется в разметке
- [ ] Все фото кейсов соответствуют их содержанию
- [ ] Meta-теги локализованы на всех языковых версиях
- [ ] Капс используется только для лейблов/заголовков/кнопок, не для основного текста
- [ ] Все анимации проверены с `prefers-reduced-motion: reduce`
- [ ] Сайт адаптивен и протестирован на мобильной версии
