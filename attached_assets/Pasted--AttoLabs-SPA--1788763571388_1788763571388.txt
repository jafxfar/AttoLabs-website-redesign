# Промпт: сборка сайта AttoLabs (многостраничный, не SPA)

Используй этот промпт как техническое задание для AI-инструмента (Claude Code и т.п.) или разработчика, который будет собирать сайт с нуля.

---

## Ключевое требование: многостраничная архитектура, НЕ SPA

Сайт должен быть **многостраничным** — отдельные маршруты с полноценной серверной отрисовкой (Next.js App Router, каждая страница — свой route-файл), а НЕ одностраничное приложение со скроллом и якорными ссылками.

Конкретно:
- `/` — главная
- `/cases` — все кейсы с фильтрами
- `/cases/[slug]` — отдельная страница каждого кейса (не модалка, не разворачивающаяся карточка)
- `/about` — о нас
- `/cooperation` — сотрудничество
- `/careers` — карьера
- Локализация как отдельные под-маршруты: `/ru/...`, `/de/...` (или через next-intl/i18n роутинг), а не переключение контента через JS без смены URL.

Требования к реализации:
- Переходы между страницами — обычная навигация (`<Link>`), с реальной сменой URL и возможностью открыть любую страницу напрямую по ссылке, без прогрузки всего сайта в один DOM.
- Общие элементы (навигация, футер, форма) — как layout-компоненты, переиспользуемые между страницами, а не через условный рендеринг секций одной страницы.
- Framer Motion `AnimatePresence` можно использовать для плавного перехода между страницами (fade/slide), но это переход между реальными маршрутами, а не между состояниями одной SPA-страницы.
- SEO-критично: у каждой страницы — собственные, локализованные meta-теги (title, description, og:*), а не один общий набор на весь сайт.

---

## Жёсткое требование: без generic/AI-slop компонентов

Не использовать шаблонные, "сгенерированные по умолчанию" паттерны, которые не были явно частью брифа. Конкретный список того, что запрещено:

**Визуальные клише:**
- Универсальный "SaaS-набор": одинаковые скруглённые карточки с одинаковой мягкой серой тенью (`rgba(0,0,0,.1)`) на каждый блок без разбора важности контента.
- Декоративные градиентные заливки "для красоты", не несущие смысла.
- Одинаковый border-radius на вообще всех элементах вне зависимости от их роли.
- Абстрактные стоковые иллюстрации (люди у ноутбуков, абстрактные блобы, 3D-шарики) — используем только реальные фото кейсов или осмысленную графику, привязанную к контенту.

**Текстовые клише ("шаблонный хром"):**
- Не добавлять "→" в конце кнопок и ссылок по умолчанию — только если это часть реального стиля AttoLabs (сейчас в оригинале это есть у "Читать историю полностью" — это можно оставить, т.к. это существующий паттерн бренда, но не размножать его на все остальные кнопки без надобности).
- Не использовать мета-строки через точку-разделитель ("A · B · C") там, где для этого нет содержательной причины.
- Не добавлять эйбраун-лейблы над каждым блоком просто по привычке — эйбрауны оставляем только там, где они уже часть системы AttoLabs (капс-лейблы у секций), не изобретаем новые бессмысленные.
- Не выдумывать generic-копирайтинг ("Революционные решения для вашего бизнеса", "Инновации без границ" и т.п.) — весь текст должен быть предметным и по существу задачи, как в разделе копирайтинга брифа.

**Анимационные клише:**
- Не делать одинаковый fade-up "на появление" у каждой секции при скролле — это самый явный маркер шаблонной генерации.
- Не добавлять hover-анимацию на каждую карточку одинаково — анимация должна отвечать на действие пользователя (открытие, фильтрация, подтверждение), а не быть декорацией по умолчанию.
- Один осознанный акцентный анимационный момент на странице — не больше.

**Структурные клише:**
- Не добавлять numbered-маркеры (01/02/03) там, где контент не является реальной последовательностью (уместно только для кейсов-нумерации, которая уже есть у AttoLabs, и для шагов процесса — это настоящая последовательность).
- Не плодить одинаковые по весу блоки — визуальная иерархия должна отражать реальную важность контента (кейсы важнее тегов индустрий).

**Важное уточнение по капсу и моно-шрифту:** это НЕ AI-slop в данном случае — это подтверждённая реальная айдентика AttoLabs (см. бренд-бриф). Капс для лейблов/навигации/кнопок и моно-шрифт для технических элементов — сохраняем как есть, это не шаблонный дефолт, а осознанный существующий стиль бренда. Не путать с генерацией "ALL-CAPS eyebrow label" из ниоткуда — здесь она обоснована.

## Проверка перед сдачей

Перед тем как считать страницу готовой, разработчик/AI должен пройти по каждому пункту:
- [ ] Каждая страница открывается по прямому URL и не зависит от того, что пользователь "проскроллил" с главной
- [ ] Ни один компонент не скопирован "по умолчанию" без привязки к реальному контенту AttoLabs
- [ ] Все анимации отвечают на действие или являются частью одного продуманного вступительного момента — не разбросаны декоративно
- [ ] Копирайтинг предметный, без generic-фраз про "инновации" и "трансформацию" без конкретики
- [ ] Визуальная иерархия отражает реальную важность блоков, а не одинаковый вес каждой карточки
